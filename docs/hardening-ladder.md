# 加固阶梯：用不断增强的靶标测出真实缺口

> 目的不是"再评审一遍"，而是把一个可复现的对抗测试跑起来：靶标逐级加固，插件逐级修补，每一级都有数字。
> 全部数据来自本机实测，脚本见 `scripts/harden-ladder.mjs`，样本与 JSON 落在 `dist/ladder/`。

## 1. 为什么要阶梯，而不是一次性难样本

一次性给一个"很难"的样本，只能得到"行/不行"；不知道**从哪一级开始不行**，也就不知道该先补什么。
阶梯的设计是**同一份 ground truth，只换保护方式**：6 个层级包含完全相同的 5 个端点、20 个追踪标记、13 个反分析标记、6 类 IoC，差别只在编码与结构。这样每一层的召回率可以直接横向比较。

| 层级 | 保护方式 | 想验证的能力 |
| --- | --- | --- |
| L0 | 全明文 | 对照组：基础扫描是否完整 |
| L1 | 奇偏移 UTF-16LE + 单字节 XOR | 1.5.0 已有的解码通道 |
| L2 | 4 字节重复密钥 XOR（全局相位）+ 长度前缀记录 + 嵌套 base64(XOR) | 多字节密钥恢复 |
| L3 | RC4 配置块（密钥以 ASCII 写在旁边）+ 栈字符串 + 反序字面量 | 熵区定位、密钥候选、明文边界、栈串重组 |
| L4 | L3 + 导入表只剩序号 + 一张 32 位 API 哈希表 | 无名字导入时的 API 恢复 |
| L5 | L4 + 每份样本唯一的归属水印（canary / 随机子域） | 反追踪：能否识别"这份拷贝会指认我" |

靶标是结构合法的 PE32：真实导入描述符链、`.rdata` + 高熵 `.text`、RC4 块放在 `.rdata` 尾部。没有编译器依赖，`npm run ladder` 即可重建。

## 2. 召回率：修补前后

`npm run ladder -- --legacy` 用同一份样本复现 1.5.0 的解码管线（关闭多字节 XOR、熵区解密、栈串、反序），所以下表是**同靶标对照**，不是引用旧结论。

| 层级 | 1.5.0 综合 | 1.6.0 综合 | 追踪面 14 | 反分析 7 | IoC 8 | 隐藏端点 3 |
| --- | --- | --- | --- | --- | --- | --- |
| L0 明文 | 100% | 100% | 14/14 | 7/7 | 8/8 | 3/3 |
| L1 单字节 XOR | 100% | 100% | 14/14 | 7/7 | 8/8 | 3/3 |
| L2 4 字节 XOR | **8.2%** | **100%** | 1/14 → 14/14 | 1/7 → 7/7 | 1/8 → 8/8 | 0/3 → 3/3 |
| L3 RC4 配置块 | **8.2%** | **100%** | 1/14 → 14/14 | 1/7 → 7/7 | 1/8 → 8/8 | 0/3 → 3/3 |
| L4 序号 + API 哈希 | **0%** | **100%** | 0/14 → 14/14 | 0/7 → 7/7 | 0/8 → 8/8 | 0/3 → 3/3 |
| L5 归属水印 | **5%** | **100%** | 0/14 → 14/14 | 0/7 → 7/7 | 2/8 → 8/8 | 0/3 → 3/3 |
| **均值** | **36.9%** | **100%** | | | | |

L5 的"归属水印"单独计分：1.5.0 只是把水印字符串当普通文本捞出来（2/2），1.6.0 会**判定它是归属水印并给出处置建议**（2/2 且 `level=high`）。这是两种不同的能力，前者是"看见了"，后者是"知道它意味着什么"。

## 3. 每一级具体补了什么

### L2：4 字节 XOR —— 一次一致性命中就把密钥钉死

`crib dragging`：假设明文里出现已知前缀（`https://`、`HKLM\`、`Mozilla/`、`C:\`、`Firebase`…）。对长度 L≤4 的重复密钥，8 个 crib 字节会给每个密钥位**两次以上**约束。随机位置同时满足 4 个相位约束的概率约 2⁻³²，所以不需要"密钥长得像不像"这种主观判断。

- 发现窗口只扫前 96 KB（O(位置×crib×密钥长度) 的扫描曾让 1 MB 文件耗时 1.2 s），确认后的密钥再作用于完整 512 KB 窗口，召回不依赖块的位置。
- 确认通道放宽了"像不像单词"的过滤：`readableLoose` 允许 `cpuid`、`VMXh` 这类 4–5 字符 API 名——它们是真实标记，但会被"必须有语义锚点"的规则误杀。

### L3：RC4 —— 熵区定位 + 候选密钥 + 明文边界

三步都不是新算法，关键是**用证据而不是用命名来判断**：

1. **熵区**：512 字节块、阈值 7.2。（128 字节块连纯随机数据都到不了 6.5，这个坑踩过一次。）
2. **候选密钥**：从可打印串里取，优先"离熵区近"和"名字像密钥"（`key=`/`secret`/`cfg`/`salt`）。`cfg=rc4;key=LadderCfgKey2024!;build=debug` 这种配置行会被切成 `key=...`、`LadderCfgKey2024!` 两个候选——不切就只能拿到整行，解不开。
3. **对齐**：RC4 是位置相关的流密码，熵区起点常常落在块边界内侧。逐字节搜索 ±8 KB，用"连续 16 字节全可打印"做筛选（随机数据命中率约 10⁻⁷），再拿语义锚点复核。
4. **边界**：解密长度不能停在熵区末尾（会截掉尾部字符串）。改用 64 字节滑动窗口：可打印比例跌破 55% 即判定明文结束——明文约 95%，错误尾部约 37%。

### L3 附带：栈字符串与反序字面量

- **栈字符串**：连续 3 段以上、间隔 ≤32 字节的短立即数，拼起来能读通才算命中；取"最长的可读拼接"，否则会把 `https://telemetry.` 当成结果。
- **反序**：整串反转后能读通、正读不通时才报，避免把每个普通字符串都翻一遍。

### L4：导入表只剩序号 —— API 哈希表恢复

哈希表里没有名字，只有 32 位值。做法是**建一次索引再查表**：5 种常见算法（ROR13 / CRC32 / djb2 / FNV-1a / sdbm）× 约 200 个 API 名（含小写变体）→ `Map<hash, 名字>`，然后按 4 字节对齐扫描。

- 只在"具名导入 < 24 个"时才扫，正常二进制不付这个成本。
- 命中一律标 `evidenceSource: api-hash`、`confidence: low`：**名字在表里**不等于**这个 API 被调用**，不能和真实导入混为一谈。

### L5：反追踪的真正盲点 —— 归属水印

"反追踪"容易被理解成"样本会收集我的 IP/设备号"。但还有一种更安静的方式：**每个分析者拿到的拷贝不一样**。样本里嵌一个唯一 token（`canary=`、随机十六进制串、随机子域），不联网也能工作——报告、截图、逐字引用一旦流出，发布方立刻知道是哪一份。

`detectAttributionCanaries()` 识别四类：显式参数、UUID、16–48 位混合十六进制串、随机子域标签。它同时**明确说明局限**：找不到不等于没有（水印可能来自下载账号、签名安装包或服务端 build ID），并把"记录后脱敏"写进防护清单，而不是建议删除证据。

## 4. 顺带修掉的两个真实缺陷

1. **`.example` 域名不算域名**：`IOC_RULES` 的 TLD 白名单漏了 RFC 2606 保留 TLD，导致所有测试/实验室样本的裸域名永远检不出。已补。
2. **纯数字指标被"像不像单词"过滤掉**：`203.0.113.77` 没有字母，`letters/len < 0.5` 直接判死。已对 IPv4 形态单独放行。

## 5. 性能

| 场景 | 1.5.0 | 1.6.0 |
| --- | --- | --- |
| 1 MB 高熵二进制，深字符串 | 约 60 ms | 167 ms |
| 同一文件，未优化的 crib 扫描 | — | 1196 ms（已优化掉） |

代价是真实的：多字节 XOR + 熵区解密让单文件深扫慢约 2–3 倍。换来的是 L2–L4 从个位数召回变成 100%。对 64 MB 上限的样本，深扫集中在 512 KB 窗口 + 96 KB 发现窗口，不会随文件线性膨胀。

## 6. 仍然测不出来的东西

阶梯只能测"静态可恢复性"。以下仍是空白，且不应假装有：

- **运行时解密**：密钥由服务端下发、或依赖执行环境计算的配置，静态无解；需要 Frida/调试器侧的观测。
- **控制流混淆**：本阶梯不涉及 MBA、虚机化、字符串加密+间接跳转；插件的 `packers` 只做熵/节区/签名启发式，不能替代结构比对。
- **水印的"不可见"变体**：改代码布局、调整常量、插入等价指令都能编码信息。当前只覆盖数据层水印（字符串/端点），代码层水印没有做。
- **API 哈希的非标准算法**：自定义哈希、加盐、按模块基址偏移都不在 5 种之内；这类只能靠反汇编里找比较循环。
- **误报率没有独立测量**：L0 干净对照在 `npm run demo` 里是 0 误报，但阶梯本身只测召回；解密通道的假阳性需要另一组高熵负样本才能量化。

## 7. 复现

```bash
npm run ladder                                  # 生成 dist/ladder/L0..L5.exe + ladder.json
npm run ladder -- --legacy --label baseline     # 同一批样本跑 1.5.0 管线
npm test                                        # 177 项，含 9 项新增能力回归
npm run demo                                    # 真实装配下的端到端能力演示（62/62）
```
